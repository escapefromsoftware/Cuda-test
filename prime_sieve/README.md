# 1000以下の素数：エラトステネスの篩

独立したCUDAプログラム。上限は `eratosthenes.cu` の `limit = 1000`。
GPUの1ブロック・256スレッドで、表の初期化、候補の判定、倍数の除外を実行する。
表は共有メモリに置き、各素数の倍数をスレッドで分担する。
素数ごとに全スレッドを同期し、前の段階の結果を次の候補判定に反映する。
CPUはGPU結果の受け取り・表示と、試し割りによる全件検算を行う。
このPCでは、ワークスペースのルートから次のコマンドでビルド・実行できる。

```powershell
.\CUDA\prime_sieve\build.bat
```

`build.bat` はこのPCのVisual Studio 18 CommunityとCUDA 13.3のパスを使用する。
`-arch=sm_86` はこのPCのRTX 3070用。

## 時系列の表示

実行すると、次の順番を表示する。

1. CPUのCUDA準備 → GPUメモリ確保 → カーネル起動 → 完了待ち → 結果転送。
2. GPUが実行中に記録した30段階を、CPU側で実行後に順番に表示。
3. CPUで全件検算 → 素数一覧と回数を表示 → 終了。

CPUのログの `+... ms` はプログラム開始からの実経過時間。
GPUの各段階には `p`、素数か合成数か、除外対象の例、除外回数、
新しく除外した数の個数、残る候補数を表示する。
例えばp=2では499個を初めて除外し、残り500個。
p=3では331回の除外処理のうち新たに166個を除外し、残り334個。
p=4はすでに合成数と分かっているのでスキップする。
最後のp=31の段階で、残る168個が素数として確定する。

GPUの `cycles A..B` は、同じスレッド0で `clock64()` により記録した
開始・終了のサイクル数（カーネル内のスレッド0開始からの差）。
CPUのミリ秒とは別の時計であり、GPUスレッドの待ち時間も含む。
段階内のスレッドは並列に動くため、表示する倍数の数値順は
個々のスレッドの実行順序を表さない。GPUログは実行後の記録の表示。
ログ記録・回数計測の処理もあるため、速度比較用の実装ではない。

## 手順

1. 0〜1000の表を用意し、0と1を素数候補から除外する。
2. `p = 2` から `p*p <= 1000` の間、残っている素数を選ぶ。
3. `p*p, p*p+p, p*p+2p, ...` を合成数として除外する。
4. 表に残った2〜1000の数を表示する。素数は168個、最大は997。

`p*p` より小さい倍数は、すでに小さい素数で除外済み。
また合成数は平方根以下の素因数を必ず持つため、`p` は31まででよい。

## 繰り返し回数

倍数の除外は、全GPUスレッドが実行した除外処理の合計を数える。
比較・加算・代入をそれぞれ別の演算として数えた値ではない。
倍数への代入は、その数がすでに除外されていても1回と数える。

| p | 最初の倍数 p² | 全スレッド合計の倍数除外回数 |
|---|---|---|
| 2 | 4 | 499 |
| 3 | 9 | 331 |
| 5 | 25 | 196 |
| 7 | 49 | 136 |
| 11 | 121 | 80 |
| 13 | 169 | 64 |
| 17 | 289 | 42 |
| 19 | 361 | 34 |
| 23 | 529 | 21 |
| 29 | 841 | 6 |
| 31 | 961 | 2 |
| **合計** | | **1,411** |

各素数pに対する回数は `floor(1000/p) - p + 1`。
したがって上記11個の素数についての和は1,411回となる。
1つの素数についての最大回数は、p=2の499回。
異なる合成数を初めて除外する回数は831回（999個の候補 − 168個の素数）。

## CUDAでの繰り返しと並列処理

- 外側の篩の段階は `p=2..31` の30回。候補の判定は各段階でスレッド0が1回行う。
- 実際に倍数を除外する素数は11個。
- 倍数除外の総仕事量は1,411回、候補判定を足すと1,441回。
- p=2で499個の倍数を256スレッドに配るため、1スレッドの内側ループは
  **1つの素数につき最大2回**。これは全体の総演算回数ではない。
- カーネル起動は1回。並列化しても、除外対象の総数は減らない。
- GPUのatomic演算で除外回数を計測し、CPUで数式による回数と照合する。

上限1000が固定されているため、この実装の回数は毎回同じ。
この意味で最大回数も上記の値になる。GPUの初期化・結果の書き戻し、
同期・カウンタ更新、CPUの表示・検算、ループの終了判定などは
篩の総仕事量1,441回には含めていない。
以前のCPU版で初期化・表示走査まで含めた3,441回という値は、
このCUDA版の全スレッドのループ実行数を表すものではない。

一般の上限Nに対する通常の篩の総仕事量は O(N log log N)、空間は O(N)。
このサンプルは上限1000専用（共有メモリの表と32要素のカウンタを使用）。
表は固定サイズなので、上限を大きくするには設計の変更が必要。
